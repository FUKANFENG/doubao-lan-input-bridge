# 豆包语音输入桥 React/Electron 音频版

这是 React 桌面 GUI + 内置局域网 Web 服务版本。除手机语音输入到 Windows 自动粘贴外，还支持“电脑声音到手机播放”。

## 功能

- 桌面端显示二维码，手机扫码打开 Web UI。
- 手机端用豆包输入法语音转文字，点击发送后 Windows 自动粘贴到当前焦点。
- 手机端保留：发送后清空、末尾加换行、发送后回车、回车延时。
- 手机端顶部提供自动 / Windows / Mac 三个目标系统按钮，点击即可直接切换：
  - 自动：发送瞬间识别 Windows 当前前台应用，优先使用该应用的绑定规则。
  - Windows / 远程 Windows：发送后模拟 `Ctrl+V`。
  - Mac 远程：发送后模拟 `Win+V`，常见远程工具会映射为 macOS `Command+V`。
- 支持按应用自动匹配粘贴方式：
  - 例如把 Codex 绑定为 Windows，把 AnyDesk、GameViewer 等远程工具绑定为 Mac 远程。
  - 手机页面会显示电脑当前前台应用，可直接点“绑定为 Windows”或“绑定为 Mac”。
  - 桌面 GUI 也可使用“3 秒后绑定”，点击后切换到目标应用即可捕获。
  - 用户绑定优先于内置远程工具提示；没有规则时普通应用默认使用 Windows。
  - 规则按 Windows 进程名保存，重启程序后仍然有效。
- 发送按钮位于文本框上方，并在页面滚动时吸附在手机屏幕顶部，输入法键盘弹出后仍可直接发送。
- 手机端保留最近 10 条输入记录：
  - 发送前先保存，因此发送失败时文字仍可找回。
  - 点击记录可填回文本框，也可点击记录右侧“发送”直接重发。
  - 自动保存未发送草稿；文本框被清空时，上一份非空内容会收入历史。
  - 历史和草稿保存在当前手机浏览器本地，不上传到其他服务。
- 粘贴模式支持自动、Windows、Mac 远程。
- 新增电脑声音桥：
  - 手机扫码后点击“开始播放电脑声音”。
  - 电脑端点击“开始采集”。
  - Windows 通过 Electron system audio loopback 捕获电脑输出声音。
  - 音频转为 16-bit PCM，通过 `/audio` WebSocket 发给手机。
  - 手机用 Web Audio API 从扬声器播放。

## 使用步骤

1. 先完全退出正在运行的旧版本，避免旧服务继续占用端口。
2. 运行新版 EXE。
3. 手机和电脑连接同一个局域网。
4. 手机扫码打开页面，并确认页面标题旁显示当前版本号。
5. 推荐在手机页面顶部选择“自动”。第一次使用某个应用时：
   - 电脑上先点一下目标应用。
   - 在手机的“应用自动匹配”区域确认当前应用，然后绑定为 Windows 或 Mac。
   - 之后保持“自动”即可，发送时会按前台应用自动切换。
6. 临时不想使用规则时，可直接点击 Windows 或 Mac 按钮手动覆盖本次发送方式。
7. 电脑先点到目标输入框，再在手机页面发送。需要找回文字时，可在“最近输入”中填回或直接重发。
8. 播放电脑声音时：
   - 手机上点击“开始播放电脑声音”。
   - 电脑端点击“开始采集”。
   - 电脑端显示正在推送后，手机会播放电脑输出音频。

## 音频限制

- 系统音频 loopback 当前按 Windows 实现。
- 手机浏览器必须先由用户点击“开始播放”，否则浏览器会阻止自动播放声音。
- 如果 Windows 完全没有可用输出设备，loopback 可能没有可捕获的系统声音。此时需要启用一个音频输出设备，或安装虚拟声卡/虚拟音频线。
- 局域网质量会影响延迟和稳定性。
